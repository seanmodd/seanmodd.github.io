How to use this guide

A migration program, not one mega-prompt

Each phase creates artifacts that become the verified input to the next phase. Structural phases preserve pixels. Visual redesign decisions happen only after the component contract is stable.

01

Run in order

Do not jump straight to Figma generation or component rewriting. Inventory and classification prevent the current chaos from being copied into a new folder.

02

Fresh agent session

Use a fresh coding-agent session for each phase or named wave. Paste the complete prompt from this site from the repository root.

03

One PR boundary

Every phase is independently reviewable and reversible. Repeatable waves are intentionally split so a failed migration never blocks the entire program.

04

Prove, then delete

Legacy components and selectors stay behind compatibility adapters until all consumers are migrated and automated usage counts reach zero.

Non-negotiable program rule

Do not ask an agent to “clean up the design system” across the whole repository. That wording invites a rewrite, silent visual drift, and new abstractions that ignore years of product behavior.
