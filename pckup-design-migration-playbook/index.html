Strangler migration · no big-bang rewrite

Production frontend modernization program

Turn Pckup’s existing frontend into a real design-system platform.

This guide is deliberately built for an established, high-complexity Next.js application—not a greenfield UI kit. It preserves the existing token pipeline, tests, production behavior, Figma assets, and delivery controls while introducing the missing canonical component layer and migrating every surface onto it in bounded waves.

Start Phase 0

Non-negotiables

  • Inspect current main before trusting any historical fact.
  • One bounded phase or migration slice per agent run.
  • Preserve production behavior and visuals unless a decision explicitly changes them.
  • Keep existing tokens and CI; replace the missing component architecture.
  • Never delete a legacy path without static and runtime zero-use evidence.
  • Figma receives only canonical components—not every rogue implementation.

Current reality

Strong foundations. Fragmented component ownership.

Tokens, themes, validation, and Figma Variables exist. Global stylesheets, route-local controls, copied shells, and oversized components still carry most of the actual interface architecture.

Migration method

Strangler architecture, not replacement.

Canonical components are introduced beside legacy code, adopted through bounded consumers and compatibility adapters, then old implementations are retired only after verified zero-use.

Target state

One contract across design, code, tests, and delivery.

Each production component has a typed API, owned styles, examples, tests, a Figma counterpart, Code Connect, usage telemetry, and a documented migration path.

Target paradigm

Build the missing canonical layer

The migration does not replace Pckup’s application. It creates a stable platform between foundations and product composition, then moves existing surfaces onto it.

Authority model

One owner for every kind of truth

Two-way tooling works only when authority is explicit. Circular ownership creates drift and accidental overwrites.

Steady state

The workflow that replaces design drift

The final phase makes this the default path for every future interface change.

01

Classify

Foundation, primitive, behavior, pattern, shell, or product composition.

02

Reuse first

Search the manifest, code library, Figma library, and approved exceptions before creating anything.

03

Design the contract

Define anatomy, API, states, accessibility, responsive behavior, tokens, and migration plan before implementation.

04

Implement together

Code, owned styles, examples, tests, Figma component, and Code Connect land as one governed change.

05

Adopt and measure

Migrate bounded consumers, watch coverage and regressions, then remove superseded paths.

06

Enforce

CI blocks new raw controls, unowned global selectors, visual inline styles, and undocumented exceptions.
